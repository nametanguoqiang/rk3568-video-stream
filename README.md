# RK3568 视频采集与推流终端

在 RK3568 开发板上打通从摄像头采集到网络推流的完整链路。

> 项目进行中，当前完成到第 3 步（V4L2 设备探测）。采集、推流、抓拍等模块在后续步骤实现，进度见下表，没做的部分不写成已完成。

## 为什么做这个项目

之前做的项目都在应用层，界面、协议、文件传输，数据是别人准备好的。这个项目要从摄像头一路打通到网络，中间每一层都自己管：V4L2 的缓冲、多线程的同步、网络的异常、长时间运行的资源占用。

目标不是把画面显示出来，是把一条实时数据链路做稳，并且能说清每一处为什么这么设计。


## 运行

```bash
# 传到板子
scp probe root@<板子IP>:/root/

# 运行，参数是设备节点
ssh root@<板子IP> "chmod +x /root/probe && /root/probe /dev/video0"
```

输出包含驱动名、设备名、采集类型（单平面或多平面）、支持的像素格式和分辨率范围。

## 关键设计

**为什么用 mmap 四缓冲**：read 方式要内核拷到用户态，一次拷贝。mmap 把内核缓冲直接映射进进程，零拷贝。四块是周转和内存的平衡点，两块容易卡，太多浪费。

**为什么用环形缓冲**：视频是定长的、连续的，旧的没用了就扔。环形缓冲一次分配用到底，不会碎片，也不会因为 malloc 阻塞采集线程。

**为什么丢最旧的一帧**：视频要实时，丢新的会让延迟越攒越大。

**为什么先做 HTTP MJPEG 不做 RTSP**：MJPEG 不需要编码器，摄像头直接出 JPEG，两天能通。RTSP 要 RTP 打包和 SDP 协商，工作量五倍。
